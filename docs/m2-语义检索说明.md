# M2 语义检索实施说明

分支：`m2/semantic`。按《席间索_技术实现方案》M2「模糊增强」核心路径实施：ONNX 语义 + embedding 子块 + RRF 融合 + 预热 + 超时降级。模型分发方式已拍板：**INT8 模型内置进安装包**（关闭文档开放问题 3）。

## 一、架构与口径对照

| 方案条款 | 实现 |
|---|---|
| §7.1 模型 `bge-small-zh-v1.5` / 512 维 / INT8 | `models/bge-small-zh-v1.5/model.onnx`（Xenova 导出的量化版），运行时 `ort 2.0.0-rc.10 (load-dynamic)` 加载 |
| §7.1 CLS pooling（非 mean） | `embed.rs::encode` 取 `last_hidden_state[0][0]` |
| §7.1 查询前缀 `为这个句子生成表示以用于检索相关文章：` | `QUERY_PREFIX`，仅查询侧拼接 |
| §7.1 L2 归一 + 点积检索 | 写入前与查询侧均 `l2_normalize`，检索用 `dot` |
| §7.1 512 token 截右侧 / CPU 2 线程 / batch=1 | tokenizer truncation Right；session intra_threads=2；单条 encode |
| §7.6 语义子块 400 字窗口 + 50 字重叠、句号处断 | `split_subblocks`；结果单位永远是展示 chunk |
| §6.5 RRF k=60，w_fts=1.0 / w_like=0.7 / w_vec=1.0 | `search.rs::add_rank`（原有）+ 语义路 `via="semantic"` |
| §6.5 向量路每 chunk 只取最好子块 rank | `semantic_chunk_ranks` 对每 chunk 取最大子块分再排序 |
| §7.2 向量导入期计算，查询只 encode 一句 | `import_one` 编码子块入 `embedding_chunks`；查询单条 encode |
| §7.3 预热不挡主窗 / 失败降级 / 当次失败不算查询失败 | `main.rs` 启动预热线程 + 状态机；`search` 语义路 `Err` 即降级 |
| §7.5 模型强校验 | `embedding_meta` 记 model_id + `model.onnx` 内容指纹 + pooling + 查询前缀，任一不符 → 语义路禁用、下次导入/补算清空重算 |
| §8 查询向量 ≤800ms | `SEMANTIC_BUDGET_MS`，超时丢语义 |

## 二、关键事实

- **端到端已验证**（`tests/semantic_e2e.rs`，模型存在才跑）：口语查询「想找个地方小酌一杯，听说有家酒馆招牌挺特别」（与样例正文零共享词）语义第 1 名命中「断桅酒馆」；无模型降级路径、backfill 补算路径均通过。全程 ~0.26s。
- **口径经 golden 校验**：分词补上 `[CLS]/[SEP]` 后（此前漏加，所谓 CLS 池化实际取到首个正文 token，与官方实现余弦仅 0.82），逐句余弦 0.9878–0.9919。
- **下载源绕过**：GitHub 被墙，ort 禁用默认二进制下载（`load-dynamic`），onnxruntime.dll 取自 NuGet 镜像（`Microsoft.ML.OnnxRuntime 1.22.0`）；模型取自 hf-mirror。一键脚本 `scripts/fetch-model.sh`（产物 `models/` 已 gitignore）。模型目录解析兼顾开发态：exe 在 `target/` 下时向上找到仓库根的 `models/`，所以 `run-demo.bat` 直接跑也有语义（此前只有安装包布局能找到，开发态一直显示「未装模型」）。
- **状态可见**：底栏右下角「语义 · 开 / 准备中 / 不可用 / 未装模型」，悬停有说明；降级查询状态栏带「仅关键词」；命中卡片带「语义」角标（§6.6 不给生造词上高亮）。
- **打包**：`package-release.ps1` 自动把模型与 onnxruntime.dll 进 zip（缺失则打纯词法版并提示），安装/卸载脚本同步处理。zip 约 4.9MB → ~18MB。

## 三、与方案的差异 / 待办（诚实清单）

1. **§7.1.1 golden 向量门禁**：已落地。参考向量由 `scripts/gen-embed-golden.py`（官方 transformers 实现，CLS + L2，查询加前缀）生成，落盘 `testdata/embed_golden.json`（12 句，进 git）。
   - **门槛偏离方案（已拍板）**：方案给 INT8 定 0.995，但 bge-small-zh-v1.5 的 INT8 产物实测最差 **0.9878**（同仓库另两个量化产物更差：int8 0.949 / uint8 0.975），而 FP32 产物 **0.999999**——说明导出无误、差距纯属量化损失，故门槛校准为 **0.98**。
   - **门禁已见效**：首次跑通即以 0.82 余弦抓出 `embed.rs` 分词未加 `[CLS]/[SEP]` 却按 CLS 取池化的口径 bug（修复后 0.99）。
2. **§13.3 semantic 评估集**：检索评估框架已可复用，≥30 条无共享词用例的数据集待扩充；M2 发布门槛（semantic Recall@10 ≥0.70）待数据集就位后跑。
3. **§5.2.1 重导入向量复用（P2）**：未做。重导入按 CASCADE 删除后全量重算该文档向量（当前规模秒级，无感）。
4. **§7.2 查询向量 2 分钟缓存**：未做。当前仅回车触发查询，无重复编码。
5. **向量内存缓存（§7.5）**：未做。每查询从 SQLite 现读向量（600 条仅 1.2MB）；十万级子块后再做内存驻留。当前已去掉逐行 `Vec` 分配（直接对 BLOB 求点积），并加扫描预算：每 512 行查一次耗时，超 `SEMANTIC_BUDGET_MS` 即停手返回部分结果（宁可少召回也不冻窗口）。
6. M2 其余非模型项（别名 tombstone、source_rank、复制公开过滤、文件夹监听）属后续批次。

## 四、运维要点

- **换模型**：改 `models/` 里的模型文件后重启即可。`embedding_meta.model_version` 存的是 `model.onnx` 的内容指纹（sha256），换文件必变；校验不符时语义路立即降级词法，并在下次导入/补算时清空旧向量全量重算。之所以存指纹：`model_id` 是编译期常量，同名换文件时它不变，只比它等于没比。
- **补算时机**：模型预热完成、打开/切换库、导入完成、点「试用样例」都会触发一次缺向量补算（后台线程，状态栏显示进度；补算期间库暂时不可检索）。补算条数与逐条警告并入状态栏，不再静默丢弃。
- **模型缺失**：语义状态「未装模型」，纯词法检索完全不受影响；现有全部测试不依赖模型（golden 门禁可用 `GOLDEN_REQUIRE_MODEL=1` 强制要求模型在场）。
- **性能**：查询侧单条 encode 在普通 CPU 上为几十毫秒量级，远低于 800ms 预算；导入侧向量计算与 LLM 拆条一样在后台线程，不冻窗口。向量编码一律在写事务外完成，避免长时间占 SQLite 写锁。
